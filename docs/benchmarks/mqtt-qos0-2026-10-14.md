# MQTT QoS 0 first live-path baseline

Date: 2026-10-14. Raw results: [ten alternating runs](mqtt-qos0-2026-10-14.jsonl).

## Workload and environment

- One Connectanum MQTT 5 publisher and one Connectanum MQTT 5 subscriber on TCP loopback. The same client code and 128-byte binary payload run against the provisional Connectanum broker and Mosquitto 2.1.2, alternated five times.
- One exact topic (`bench/one`), QoS 0, 100 warmup messages acknowledged by receipt at the subscriber before 2,000 measured messages per run. The benchmark checks 2,000 distinct IDs at the subscriber and fails on loss, duplicates or unexpected payload shape.
- Dart SDK 3.13.1 macos_arm64, Apple M3 Ultra. Mosquitto runs without per-message verbose logging. `runner_rss_bytes` measures the Dart runner only; it is **not** broker RSS and cannot be compared as a broker memory result.
- Command from `packages/connectanum_router`: `dart run benchmark/mqtt_qos0.dart` for Connectanum and `dart run benchmark/mqtt_qos0.dart 127.0.0.1 18883` for Mosquitto started with `mosquitto -p 18883`.

## Observed medians

| Target | Delivered/s | p99 latency | Delivery |
| --- | ---: | ---: | --- |
| Connectanum provisional Dart broker | 38,907 | 49.9 ms | 10,000/10,000, zero duplicates |
| Mosquitto 2.1.2 | 49,116 | 38.8 ms | 10,000/10,000, zero duplicates |

The provisional Connectanum broker trails Mosquitto by about 21% in delivered throughput and has about 29% higher p99 latency for this single local workload. This is a baseline for profiling, not a portable CI gate or a claim about TLS, WebSocket, fan-out, QoS 1/2, mixed WAMP traffic or native-listener performance. The first Mosquitto run with verbose per-message logging and an earlier run set with a timed warmup delay were discarded; neither appears in the raw results.

## Next measurement requirements

The provisional [QoS 0 budget](../../tool/mqtt_benchmark_budget.json) requires at least 0.65× Mosquitto delivered throughput and at most 1.75× its p95/p99 latency, using five alternating 2,000-message runs with exact delivery. The local gate passed with throughput ratio 0.843, p95 ratio 1.204 and p99 ratio 1.204. The [CI MQTT lane](../../.github/workflows/dart.yml) passed on [PR #128's first hosted run](https://github.com/konsultaner/connectanum-dart/actions/runs/38553865524/job/115818051646): throughput ratio 1.168, p95 ratio 0.866 and p99 ratio 0.855, with 10,000/10,000 deliveries per target and no duplicates. Its uploaded raw/summary artifact is named `mqtt-qos0-benchmark`. These limits catch large regressions in the provisional path but are not the final release budgets.

A 10,000-message unpaced burst caused the Mosquitto reference to miss the benchmark's 30-second exact-delivery deadline. QoS 0 permits loss under overload, so this is not yet classified as a broker defect. It shows that the saturation, pacing, queue-depth and overload experiments must be separated from the zero-loss steady-state gate.

The [AOT process-isolated successor](mqtt-qos0-aot-2026-10-14.md) adds a bounded sustained workload and provisional broker CPU/RSS budgets. It uses a different execution method, so its throughput and latency numbers must not be compared directly with this baseline.

Before closing [#127](https://github.com/konsultaner/connectanum-dart/issues/127), extend the provisional AOT broker CPU/RSS gate to controlled long-duration and hosted evidence, run overload workloads, add fan-out and payload-size sweeps, include native negotiated TCP/TLS/WebSocket paths, and set final numeric budgets on a pinned CI runner. Preserve loss and duplicate checks in every throughput result.
