# Hosted MQTT same-source performance repeat

The [MQTT job on PR head `1f86da2e`](https://github.com/konsultaner/connectanum-dart/actions/runs/38698466939/job/116301020059) passes all twenty unchanged performance and correctness profiles. Its clean PR merge checkout is `04b50454` on AMD EPYC 9V45, `ubuntu24` image `20261012.334.1`, with Mosquitto 2.0.18. The job passes Paho and Connectanum MQTT 5/3.1.1 TCP, TLS, WS and WSS interoperability, exact 642/642 scoped MQTT Dart lines and 254/254 Python benchmark-gate lines. The [192 matched raw rows](mqtt-hosted-same-source-repeat-1f86da2e-2026-10-15-raw.jsonl) all have `received == sent * subscribers` and zero duplicates; [twenty summaries](mqtt-hosted-same-source-repeat-1f86da2e-2026-10-15-summaries.json) and the [uploaded artifact](https://github.com/konsultaner/connectanum-dart/actions/runs/38698466939/artifacts/11956260138) retain machine and commit provenance.

The native MQTT 5 TCP 64 KiB/window-32 profile measures 0.38 seconds median Connectanum broker CPU versus 0.12 seconds for Mosquitto, a **3.167×** ratio below the unchanged **4.0×** cap. Throughput is 0.959× Mosquitto, p95/p99 latency ratios are 1.145/1.094, and the maximum broker RSS is 64,827,392 bytes, below the 64 MiB budget. Native WS MQTT 5/3.1.1 throughput ratios are 0.852/0.885 against the unchanged 0.700 floors. Sustained WSS MQTT 3.1.1 reaches 5.849× throughput against its 2.0× floor.

The [preceding red run](mqtt-hosted-64k-cpu-3178e157-2026-10-15.md) tested the same production code on Intel Xeon 6973P-C with the same image and pinned Mosquitto, but measured 0.62/0.13 seconds and 4.769× for the 64 KiB CPU ratio. Other native profiles also show higher Intel CPU ratios: 128 B sustained MQTT 5 is 1.622× versus 1.249× on AMD, and MQTT 3.1.1 is 1.660× versus 1.289×. `1f86da2e` changed only checked-in benchmark documentation after `3178e157`; neither run establishes a code regression or a controlled cross-hardware margin. Keep both outcomes, the 4.0× budget, and [#127](https://github.com/konsultaner/connectanum-dart/issues/127) open until the release matrix includes repeatability on controlled hardware.

On a separate Apple M3 Ultra diagnostic, a clean-source 250,000-publication, 64 KiB/window-32 native TCP run delivered 250,000 exactly at 10,682/s. A six-second macOS `sample` with an AOT debugging-info image symbolized active copy call sites in Rust `ct_poll_mqtt_chunk`, Dart `MqttFrameDecoder._append`, Dart `NativeTransportRuntime.sendMqttChunk`, and Rust `Bytes::copy_from_slice` in `ct_send_mqtt_chunk`. Sampling identifies call sites, not a causal CPU saving: three isolated copy-avoidance trials either left local CPU unchanged or made throughput/CPU worse and were reverted. Do not infer Intel runner cost from the Apple profile.
