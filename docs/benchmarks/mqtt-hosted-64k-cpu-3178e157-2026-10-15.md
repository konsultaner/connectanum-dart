# Hosted MQTT 64 KiB broker CPU regression checkpoint

The [MQTT CI job](https://github.com/konsultaner/connectanum-dart/actions/runs/38695756281/job/116292007717) on PR head `3178e157` passes Paho/Connectanum MQTT 5 and 3.1.1 TCP/TLS/WS/WSS interoperability, scoped 642/642 MQTT Dart lines and 254/254 Python benchmark-gate lines. Nineteen of twenty profiles pass. All [192 raw matched rows](mqtt-hosted-64k-cpu-3178e157-2026-10-15-raw.jsonl) deliver exact per-subscriber counts with zero duplicates; [20 summaries](mqtt-hosted-64k-cpu-3178e157-2026-10-15-summaries.json) and the [uploaded artifact](https://github.com/konsultaner/connectanum-dart/actions/runs/38695756281/artifacts/11954876242) retain provenance. The clean PR merge checkout is `cf72c4f6` on Intel Xeon 6973P-C with `ubuntu24` image `20261012.334.1` and pinned Mosquitto 2.0.18.

The sole failure is native MQTT 5 TCP with 64 KiB payloads and a 32-message window. Across five 5,000-publication pairs, Connectanum's median broker CPU is 0.62 seconds versus Mosquitto's 0.13 seconds, a **4.769×** ratio above the unchanged **4.0×** limit. Connectanum CPU samples are 0.61–0.64 seconds and Mosquitto samples 0.12–0.13 seconds. Throughput ratio 0.880 exceeds its 0.750 floor; p95/p99 ratios 1.233/1.244, peak RSS 58.6 MB, and exact delivery pass. Re-evaluating the ten saved rows through the checked-in `compare` function reproduces `passed: false` on CPU alone.

The preceding [green checkpoint](mqtt-hosted-wss311-numeric-67912122-2026-10-15.md) used AMD EPYC 9V74 and image `20261004.327.1`: native 64 KiB CPU was 0.51 seconds versus Mosquitto's 0.16 seconds, ratio 3.188×. The current run uses different CPU hardware and image, so it does not isolate a source regression. Its native WS MQTT 5/3.1.1 ratios improve to 0.916/0.945 above unchanged 0.700 floors, and sustained WSS 3.1.1 passes its hard numeric gate at 8.288× throughput. Preserve the 4.0× CPU limit while profiling large-payload copies and collecting controlled same-source evidence; [#127](https://github.com/konsultaner/connectanum-dart/issues/127) and the milestone remain open.

Local Apple M3 Ultra diagnostics with Mosquitto 2.1.2 are not release comparisons. Five-pair 64 KiB baseline and two temporary copy-avoidance trials all measured 0.33 seconds median Connectanum broker CPU for 5,000 publications. Returning a borrowed FFI read-buffer view instead of a copied list left throughput near 10.6k delivered/s; detaching the decoder's backing storage for large PUBLISH frames lowered throughput from about 10.7k to 7.9k/s. Both changes were reverted. A five-second macOS sample during a longer run showed `_platform_memmove` among active frames, but its AOT frames were not symbolized enough to identify which copy dominates. This evidence does not justify a data-path rewrite or a relaxed budget.
