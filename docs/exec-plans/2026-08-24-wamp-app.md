# WampApp Consumer Application

Status: active
Started: 2026-08-24

## Goal

Build a production-oriented Flutter messaging example that proves the public
Connectanum packages can support account onboarding, WAMP-SCRAM, end-to-end
encrypted messaging, offline operation, rich media, calling, backup, and MCP
integration without private project assumptions.

## Architecture Contract

- Keep `examples/wamp_app/client`, `server`, and `shared` standalone so Flutter
  does not enter the root Dart workspace or package release graph.
- Consume synchronized hosted Connectanum prereleases rather than local package
  paths; only the WampApp protocol package is a local path dependency.
- Use one WebSocket endpoint with an anonymous registration realm and a
  separately authenticated application realm.
- Use standardized `wamp-scram` on the wire and Argon2id13 verifier material at
  rest. Never persist or log plaintext passwords, proofs, salts, keys, or worker
  messages beyond their required lifetime.
- Treat the router and application service as untrusted for message contents.
  Durable messages and attachments use application-level encrypted envelopes in
  WAMP binary fields; only clients hold conversation plaintext keys.
- Use WAMP for control, RPC, pub/sub, offline synchronization, attachment
  coordination, WebRTC signaling, and MCP. Use WebRTC/SRTP for call media.
- Do not present unimplemented capabilities as working UI or seed fake chats.

## Milestones

1. **Account vertical slice:** standalone packages, YAML server, anonymous
   registration, asynchronous Argon2id13 derivation, SCRAM login, responsive
   Flutter shell, verifier-only persistence, and consumer integration smoke.
2. **Identity and local trust:** per-device identity keys, encrypted local
   database, device enrollment/revocation, contact identity verification, and
   conversation-key wrapping.
3. **Durable messaging:** opaque server mailbox, receipts, reconnect cursors,
   one-to-one and group chats, read state, retry/deduplication, expiration, and
   one-time message semantics.
4. **Rich content:** encrypted attachments, images, GIFs, stickers, emoji,
   voice notes, bounded file transfer, resumability, and transfer benchmarks.
5. **User experience:** profiles, status, contacts import, global search,
   read/unread filters, themes, per-chat mute, and platform push notifications.
6. **Backup and recovery:** encrypted local export/import plus provider-neutral
   cloud backup with explicit key recovery and corruption tests.
7. **Calling:** WebRTC voice/video sessions with WAMP signaling, TURN guidance,
   call-state recovery, and mobile/web permission handling.
8. **MCP:** authenticated server tools/resources/prompts and client-side user
   consent boundaries for AI-assisted actions; no plaintext chat export by
   default.
9. **Production evidence:** threat model, abuse/rate limits, migrations,
   multi-device conflict tests, browser/mobile smokes, packaging, benchmarks,
   and full repository verification.
