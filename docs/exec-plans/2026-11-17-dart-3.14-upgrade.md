failed samples have about 32–35 MiB old-space used versus 4–6 MiB in normal

zero. This evidence does not establish retained live application objects.

The original-source probe reproduces the first-cycle failure in normal AOT
workers. Scratch-buffer reuse and a separate external MQTT input-buffer candidate
both fail hosted comparisons and are discarded. Neither change is in this PR.
The exact EVENT shape is ordinary materialized binary arguments, with no PPT,
lazy bytes or keywords. The product AOT SDK returns “VM is built without the
heap snapshot writer”; no AOT object census is claimed. JIT snapshots are
separate diagnostics and do not certify AOT memory behavior.

The fix transfers large MessagePack worker-to-boss frames
with `TransferableTypedData`, then materializes them once before native enqueue.
It avoids the managed receiver-side byte-array clone while preserving the
serialized bytes. Smaller frames and other codec paths retain their established
handoffs. The SDK's [transfer contract](https://github.com/dart-lang/sdk/blob/3.14.0/sdk/lib/isolate/isolate.dart)
provides single-owner transfer; creation copies input bytes, and mutation after
sending cannot change the received frame. This does not add a collection hook,
VM flag, delay, warm-up, workload reduction or numeric budget change.
