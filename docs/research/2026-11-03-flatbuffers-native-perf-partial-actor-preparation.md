# A joined preparation call can still retain an auxiliary child

One new current-Darwin finite fault fixture establishes a concrete boundary
for the unfinished preflight controller. The actual constructor worker joins
and remains failed/uninitialized while an actual retained auxiliary child is
still pending. The current public producer-wait continuation refuses without
scheduling another call. This is a deliberately injected preparation fault,
not an observed production or canonical-build defect.

The fixture replaces the source guard with a call to the actual auxiliary
command machinery. One declared OSError escapes the first auxiliary wait
after its child starts. The recipe-pending field remains false; the actual
auxiliary ledger retains its child. The constructor preserves that same
exception and raises. The source guard and one wait boundary are mocked;
producer provenance remains fixture and no recipe or own build receipt runs.

The serialized before view records call completion, settled start and actual
worker join, with initialized false and actor ownership unknown. The known
child is ready and its retained Popen poll returns null while auxiliary
pending is true. Public continuation refuses without changing the call index
or view. Thus worker join cannot discharge this known child or establish
physical lease lifetime.

that same actual auxiliary. It naturally returns zero with separate stdout
and stderr EOF, 29 bytes each, with full stream/file hashes matching. The
constructor remains failed/uninitialized; no state is repaired or retagged.
This direct-handle fixture wait is not a live public continuation API. The
predeclared emergency fixture fallback is unused.
