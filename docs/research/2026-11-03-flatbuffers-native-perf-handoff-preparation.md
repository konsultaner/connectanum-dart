## Source protocol and limits

A strict request binds declaration, nonce, peer and fixture context before the
producer creates its two pipes. The producer transfers only the controller's
control-write and ACK-read references, closes its local copies, then reports
completion. It retains only control-read and ACK-write. Tests exercise actual
bidirectional pipe flow and inspect the owned producer's remaining endpoints.
Each rights transfer has one H-byte send; failures never resend that operation.

Bounded framed reads always use recvmsg, rejecting malformed/truncated/unknown
ancillary data, wrong counts, unexpected metadata rights, swapped/duplicated
ends and schema/context changes. All delivered copies are tracked and made
noninheritable before adoption. Raw/partial observations remain available in
wire evidence. Failed exchanges are terminal and tear down the private socket.

For Linux source design, peer credentials describe connection time; per-message
credentials are also required. Default message credentials use real IDs, so
caller identity agreement is checked. Rights transfer requires ordinary payload
data. These are API requirements, not proof of future host support.
[Linux man-pages unix(7)](https://man7.org/linux/man-pages/man7/unix.7.html).
The future helper must connect after privilege exec, rather than authenticating
it through a controller-created socketpair. Live receive requires credential
and close-on-exec facilities without guessed constants or a portability fallback.

GLM test advice, debug and source review completed. Root rejected claims that
caller-owned source descriptors lack cleanup or metadata rights are silently
admitted: the producer's finally block owns cleanup, and metadata rights already
refuse. Do not add double-closes to a borrowed-descriptor function. The debug
correctly identified the clusters but misstated leak ordering: cleanup saw an
empty tracked set because decoding failed first. Root accepted/reproduced
cleanup masking and the unconfirmed-count evidence gap. Advice is not approval.
